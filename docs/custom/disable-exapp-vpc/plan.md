# 実装計画: 外部アプリ呼び出し Lambda の VPC 無効化オプション

## 概要

修正対象は CDK 4 ファイルのみで、変更行数は約 10 行・追加のみ・削除なし。タスク量が小さく、ファイル間で依存関係（パラメータ名の整合性）があるため、**並列化はせず単一の実装担当エージェント（または主エージェント自身）で一気通貫に実施する** のが効率的・安全。

レビューフェーズのみ並列化して、コードレビューと機密情報レビューを同時実行する。

## フェーズと実行戦略

### フェーズ 1: 実装（直列・主エージェント）

ファイル間で `disableExAppVpc` パラメータ名・型が一貫している必要があり、また 4 ファイル合計 10 行程度の修正のため、並列化のオーバーヘッドのほうが大きい。主エージェント自身が以下の順で Edit する。

1. **`packages/cdk/lib/stack-input.ts`** — Zod スキーマに `disableExAppVpc` を追加
2. **`packages/cdk/lib/generative-ai-use-cases-stack.ts`** — `TeamAccessControlStack` への引き渡し
3. **`packages/cdk/lib/team-access-control-stack.ts`** — Props と Construct 呼び出しに伝搬
4. **`packages/cdk/lib/construct/team-access-control.ts`** — Props 拡張、VPC 生成 3 択分岐、Lambda 2 つの条件付き VPC 設定

順序の理由：型の依存関係（上流が下流に流れる）を考慮し、エディタの型チェック警告を最小化する。

### フェーズ 2: 静的検証（直列）

5. `packages/cdk` で `npx tsc --noEmit` 相当（または `npm run build`）を実行し、TypeScript エラーがないことを確認
6. `cdk synth` でテンプレート生成が通ることを確認（`disableExAppVpc: false` のデフォルト挙動）

### フェーズ 3: レビュー（並列・2 サブエージェント）

実装完了後、以下 2 つのレビューを **同時メッセージ内で並列起動**：

- **エージェント A（コードレビュー、`general-purpose`）**
  - 入力: 変更ファイル一覧、design.md
  - タスク: design.md 通りに実装されているか、後方互換が崩れていないか、型整合性、副作用の有無を確認
  - 報告形式: 200 語以内の指摘リスト

- **エージェント B（機密情報レビュー、`general-purpose`）**
  - 入力: 本 PR で追加/変更された全ファイル + 新規作成された `docs/custom/disable-exapp-vpc/*.md`
  - タスク: 以下が含まれていないか確認
    - AWS アカウント ID、IAM ロール ARN、アクセスキー
    - 顧客名・案件名・社内ホスト名・社内ドメイン
    - ソース URL、内部 Slack URL、Wiki URL
    - 秘密鍵、トークン、パスワード
    - 個人氏名・メールアドレス（コミット author 以外）
  - 報告形式: 200 語以内、検出箇所をファイル名:行番号で

両エージェントの結果を踏まえ、必要なら追加修正を実施。

### フェーズ 4: レポート作成（直列・主エージェント）

7. `docs/custom/disable-exapp-vpc/report.md` を作成
   - design / plan との差分
   - 発生したトラブルと対処
   - レビュー結果のサマリ
   - 動作確認方法（実環境への deploy は本タスクの対象外）

### フェーズ 5: コミット & プッシュ（直列）

8. `git add` で本タスクで変更/作成したファイルのみをステージ
9. コミットメッセージは fork のスタイルに合わせて簡潔に
10. `git push -u origin claude/gifted-brown-HRKZC`

## 並列化判断のまとめ

| フェーズ | 並列化 | 理由 |
|---|---|---|
| 実装 | しない | ファイル間で型依存あり、規模も小さい |
| 静的検証 | しない | 順序ある |
| レビュー | **する** | コードレビューと機密チェックは独立した観点 |
| レポート | しない | レビュー結果を集約する性質 |
| コミット | しない | 順序ある |

## 想定リスクと対応

| リスク | 対応 |
|---|---|
| TypeScript 型エラー | フェーズ 2 で検出、Edit でその場修正 |
| `cdk synth` 失敗 | 差分を最小化しているため発生確率は低い、エラー時は report.md に記録して修正 |
| ビルドツールが手元で動かない（依存未インストール等） | report.md に明記、CI に委ねる |
| 機密情報レビューでヒット | フェーズ 4 前に該当箇所を修正、修正内容を report.md に記録 |
